### Findings

**1. Stripping `\p{Cf}` will break legitimate Indic / Arabic / Persian names** — `src/domain/common/schemas/name.schema.ts:9`

`INVISIBLE_CHARACTERS` strips all `Cf` codepoints, including ZWJ (U+200D) and ZWNJ (U+200C). These are not just emoji joiners — they are required for correct rendering of many South/Southeast Asian and Arabic-script names (e.g. Devanagari conjuncts, Persian `میخواهم`-style ZWNJ usage). After this change, a user typing such a name will see their characters silently mutated. The PR description correctly cites Trojan Source as motivation, but only mentions dropping the *emoji* ZWJ exemption — the collateral impact on Indic/Persian names isn't called out.

Suggestion: at minimum document this tradeoff. A safer policy is to strip only the dangerous `Cf` subset (bidi controls U+202A–U+202E, U+2066–U+2069, invisible separators, etc.) and keep ZWJ/ZWNJ. Bidi overrides are the actual Trojan-Source vector — ZWJ/ZWNJ are visually neutral and don't enable that attack.

**2. `escapeCsvFormula` is bypassed for non-string cells** — `src/modules/csv-export/v1/entities/csv-export.options.ts:34`

`csv-stringify`'s `cast.string` only fires when the value is already a string. The existing spec at `csv.service.spec.ts:407` actually shows this: `null` notes "bypass cast.string entirely" and emit empty. That's fine for `null`, but it also means if any column ever produces a `number` or `boolean` (e.g. an upstream refactor changes `note`'s type), the escape disappears silently. Defense-in-depth: add a `number` cast or coerce in the column extractor for free-text columns, or assert with a type test that `note`/`assetSymbol`/`gasTokenSymbol`/`from`/`to` are always strings.

**3. `nameBuilder` round-trip assertion is fragile under Faker variation** — `src/domain/common/entities/name.builder.ts:24`

`name.builder.spec.ts:18` asserts `sanitizeName(name) === name`. This depends on `faker.person.fullName()` never emitting a name that needs NFC normalization or has trailing whitespace. That's *currently* true for the default locale but it's a property of Faker, not enforced here. If you want the invariant to hold robustly, run the picked name through `sanitizeName` inside `nameBuilder` before padding/slicing. Bonus: padding then slicing currently can produce a name that ends with a code-point boundary mid-grapheme-cluster (e.g. truncating an `é` decomposed into `e + ́`) — though NFC + sanitize first avoids that.

**4. Misleading comment about full-width normalization** — `src/modules/csv-export/csv-utils/escape-csv-formula.ts:5`

Comment says full-width `＝ ＋ － ＠` "normalize to the ASCII forms". That's only true under **NFKC**, not NFC. `sanitizeName` uses NFC, so full-width chars survive normalization and would be rejected by the name allowlist anyway — but the CSV escaper sees the raw value, so it correctly lists them as triggers. The defense is right; the explanatory comment is just inaccurate.

**5. `ALLOWED_PUNCTUATION` includes `'` (U+0027), but users will frequently paste `’` (U+2019, curly apostrophe)** — `src/domain/common/schemas/name.schema.ts:14`

`O'Brien` works; `O'Brien` (the curly variant most macOS/iOS keyboards auto-insert) doesn't. `’` is `\p{Pf}` (final punctuation), not letter/mark/number. Consider either adding it explicitly or NFKC-normalizing curly quotes to straight before validation. Same goes for `–` (en-dash) vs `-`.

**6. `\p{N}` admits more than digits** — `src/domain/common/schemas/name.schema.ts:17`

`\p{N}` includes `\p{No}` (other numbers): vulgar fractions (`½`, `¼`), Roman numerals (`Ⅷ`), circled digits (`①`). Probably acceptable, but if the intent is "digits only" use `\p{Nd}`. Not a security issue.

**7. Empty after stripping** — `src/domain/common/schemas/name.schema.spec.ts:154`

Good test. Note that with the default `min=3`, the rejection message will be the length-min message rather than disallowed-character, which is slightly misleading UX (the user typed only invisibles, didn't violate length). Consider reordering refinements so disallowed-character fires first when nothing remains, or add a dedicated message for "empty after sanitization".
