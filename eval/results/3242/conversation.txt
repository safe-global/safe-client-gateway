### Suggestions

**1. `feature-flag.service.integration.spec.ts:23` — redundant optional chaining**

```ts
afterEach(async () => {
  if (app) await app?.close();  // `if (app)` already guards; the `?.` is dead
});
```

The `if (app)` check already narrows `app` to be defined, so the `?.` is redundant. Either drop the `if` (relying only on `?.` like every other spec in this PR) or drop the `?.`. Preferring the former keeps the codebase consistent with the pattern applied everywhere else:

```ts
afterEach(async () => {
  await app?.close();
});
```

**2. `bridge-name.entity.spec.ts:21-24` — unbounded resample loop**

```ts
let name = faker.word.noun();
while (isBridgeName(name)) {
  name = faker.word.noun();
}
```

In practice safe (`faker.word.noun()` draws from a very large vocab vs. only 20 bridge names), but with a seeded faker there's no guarantee of termination. A bounded loop with a hard-coded fallback would be strictly safer, e.g.:

```ts
let name = faker.word.noun();
for (let i = 0; i < 10 && isBridgeName(name); i++) {
  name = faker.word.noun();
}
if (isBridgeName(name)) name = 'definitely-not-a-bridge';
```

Not a blocker — flag it if you want belt-and-braces.

**3. `name.builder.ts:28` — worth noting (no change needed)**

The re-`sanitizeName()` after the slice is the right call, but after trimming trailing whitespace the result could theoretically drop below `NAME_MIN_LENGTH`. Given `SAMPLE_NAMES` and `faker.person.fullName()` outputs, this is not reachable in practice, so no change is needed — just worth being aware that the builder no longer strictly guarantees `length ≥ NAME_MIN_LENGTH` in the pathological case.
