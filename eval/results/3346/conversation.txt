#### `FeatureKey` doesn't narrow to the published keys
`src/modules/entitlements/domain/entities/feature.entity.ts:12`

```typescript
export const FEATURE_KEYS = ['safe_seats'] as const;
```

`FeatureKey = string` accepts anything, so `DTO.feature: FeatureKey` no longer enforces membership in `FEATURE_KEYS` — the OpenAPI `enum: FEATURE_KEYS` becomes a docs-only contract, drift only surfaces at the runtime integration test. Consider `export type FeatureKey = (typeof FEATURE_KEYS)[number];` so the compiler pins it too.

#### `resolveFeature` silently falls through to `Metered`
`src/modules/entitlements/routes/entitlements.service.ts:366`

```typescript
if (feature.type === FeatureType.Binary) { … }
if (feature.type === FeatureType.Value) { … }
return { …, type: FeatureType.Metered, … };
```

If a fourth `FeatureType` is ever added, an unknown type gets served as `Metered` with `resetsAt`/`quota`/`used` — no compile error. An exhaustive `switch` with a `never` assertion in the default would catch it at build time, matching the discipline used for `stockCounters`.

#### `resolveEntitlements` fans out three reads before the existence check settles
`src/modules/entitlements/routes/entitlements.service.ts:77`

```typescript
const [spaceCreatedAt, features, activeSubscription] = await Promise.all([
  this.getSpaceCreatedAtOrFail(spaceId),
  this.featuresRepository.getFeatures(),
  this.subscriptionsRepository.getActiveSubscriptionBySpaceId(spaceId),
]);
```

For a non-existent space (or the arch-review's noted case where `assertMember` throws first via the HTTP path but this method is also reachable directly), the other two queries still complete before the rejection surfaces. Not a hot-path concern with the new index, just wasted work — worth a quick order-of-ops pass if you touch the method again.

#### Migration is idempotent on `up` but not `down`
`migrations/1787148838500-seed-features.ts:12`

The `up` uses `ON CONFLICT ("key") DO NOTHING` which is nice for re-runs, but `down` deletes rows and their dependents even if the feature was inserted by something else in the meantime. Low practical risk given `ON DELETE RESTRICT`, but it's worth noting the `down()` is destructive rather than a strict inverse.

#### Minor: `FEATURE_METADATA_PREFIX` doc says `SECURITY_HUB` / `SPONSORED_TRANSACTIONS` / `SWAP_FEE_TIER`
`src/modules/entitlements/domain/entitlements.constants.ts:70`

Comment references keys that aren't in `FEATURE_KEYS` yet (`safe_seats` only). Either the doc is aspirational (fine) or catalog keys are lagging the design — worth a short note in the comment if the former.


`packaged` was pulled from `withPackage`, which already filtered `entitlements !== null`. The second `!= null` guard is dead — `packaged.entitlements` is guaranteed non-null when `packaged` is defined. Not a bug, just noise you could drop for clarity.

`src/modules/entitlements/routes/entitlements.service.ts:367`

```typescript
purchased: activeSubscription?.entitlements?.find(

),
```

Called inside a `features.map(...)`, so each feature scans the full purchased list — `O(N·M)`. With today's tiny catalog it's noise, but building `new Map(activeSubscription?.entitlements?.map(e => [e.feature.id, e]))` once outside the loop makes it `O(N + M)` and reads as clearly as the current code.

#### `getSpaceCreatedAtOrFail` is unreachable via HTTP
`src/modules/entitlements/routes/entitlements.service.ts:526`

Through `getEntitlements`, `assertMember` runs first — a deleted or non-existent space cannot have members, so it returns 403 before `resolveEntitlements` is called. The `NotFoundException` inside `getSpaceCreatedAtOrFail` only fires on races (space deleted between `assertMember` and here) or direct callers of `resolveEntitlements`. Fine to keep, but worth a short note in the comment so a future reader doesn't wonder why HTTP tests never exercise it.

#### `toEntitlementsResponse` uses `safeParse` per entitlement in a loop
`src/modules/entitlements/routes/entitlements.service.ts:494`

```typescript
const feature = FeatureKeySchema.safeParse(entitlement.feature);
```

For each entitlement it constructs a zod result to test membership in a `readonly` array. A hoisted `new Set(FEATURE_KEYS)` and a `.has()` check would be a couple of lines shorter and avoid the per-iteration parse. Nit-level.

#### Micro: unnecessary `Number()` cast
`src/modules/entitlements/domain/space-feature-usage.repository.ts:46`

```typescript
row.feature ? [[Number(row.feature), row.used] as const] : [],
```

`loadRelationIds` populates the relation with the raw FK column (`integer` in `feature.entity.db.ts`), which TypeORM returns as a number for `PrimaryGeneratedColumn`. The `Number()` wrap is a no-op — either drop it, or type `row.feature` as `number` at the call site if you want compile-time clarity.
